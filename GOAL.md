# Goal for the Calo iOS run (revised 2026-11-20, awaiting Walt's go)

Goal: Calo iOS and a construction calculator, spec-driven, until every feature passes or you are truly blocked.

Repo: ~/Developer/Calo (WaltOfAllTrades/calo, public). Branch `ios`, new `ios/` folder at the repo root; the web app and its Pages deploy stay untouched. Push the branch, open PRs, merge your own PRs into main when the gate is green. Public repo: no secrets, no personal data in commits.

Two separate apps, one install for now. Calo and the construction calculator are different products: separate specs, separate packages, separate screens, nothing shared but the design system and the test tooling. Build them inside one Xcode project under one bundle ID so I can run both from a single install; a Settings → Experiments switch picks which app the install opens as. Splitting into two App IDs is a later decision of mine, so keep the seam clean.

App 1, Calo native. Swift 6 / SwiftUI, iOS 26 minimum, iPhone, portrait, Liquid Glass throughout. Identical in function to the web app in `src/`: keypad with add/subtract intent, entry display with rolling digits, mini daily dash (logged, remaining, errors), optional name and notes fields, today's log with edit and delete, settings (daily target, show name, show notes, clear daily log), about page. Local storage only; your choice of store, logged.

App 2, construction calculator. Before writing its spec, research: the feature sets of the leading construction calculators (Construction Master Pro, BuildCalc, Handyman Calculator, Jobber, ConstructionCalc, DEWALT Mobile Pro, the fraction calculators), and their App Store and Play reviews. Collect the recurring pain points (ugly or dated UI, subscriptions and paywalls, fraction entry that fights the user, no undo, memory that clears, hard-to-read results on site, no history, confusing unit modes, tiny keys with gloves) and write them into the spec as problems to solve, each tied to a feature. Cover at least: feet-inches-fractions entry and arithmetic to 1/64 with settable precision, decimal and metric conversion, area, volume, concrete yards and bags, board feet, stairs (rise, run, stringer, headroom), roof pitch, rafters and hips, diagonal and square-up, circles and arcs, percent, tape-friendly rounding, memory, history with recall. Every formula gets a unit test against a worked example from a published source. Several visual options for keypad and display, switchable in Settings; pick a default and log why. Free, no paywall, no account.

How to work: spec first. Write `ios/spec/calo/` and `ios/spec/calculator/` (README, ontology, SPEC, features.json with dependsOn and passes, code-standards) before code, in the style of Curata's `mvp/`, then build feature by feature. Calo first, then the calculator. A `verify.sh` gate (lint, build, unit and UI tests, counts never below last green) before every merge. Adversarial review before every significant commit. Swift Testing for logic, XCUITest for flows, accessibility audits. Log every decision in PROGRESS.md; leave SETUP_STATUS.md as my briefing with the refresh-device command.

Fixed values: Team Z3W92U6PBC (Personal Team, free, automatic signing), bundle ID com.waltofalltrades.calo (tests .tests/.uitests). Never change them or entitlements to dodge an error. Free tier: no Push, IAP, iCloud, Sign in with Apple or any paid capability. One simulator and one xcodebuild at a time; shut simulators down when idle. Do not install on my phone unless it is unlocked.

Ask me nothing; decide and log. Keep going until you run out of usage.
