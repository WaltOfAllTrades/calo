## 1. Status in one paragraph
Branch `ios` holds two native iPhone products in one install under `com.waltofalltrades.calo`: **Calo**
(the web app from `src/`, rebuilt in Swift 6 / SwiftUI with Walt's original keypad design) and a
**construction calculator** at Construction Master Pro function parity (16 trade functions, exact
feet-inch-fraction engine, tape, memory, five looks). Both are spec-driven (`../spec/`), gated by
`../scripts/verify.sh`, and covered by 142 unit tests, 20 UI tests and accessibility audits. The web app and
its GitHub Pages deploy are untouched. Gate result and merge: see §9 (filled in when the queued run ends).

## 3. Approach
1. **Research first.** Two read-only agents read the App Store and Play reviews of Construction Master Pro,
   BuildCalc, Jobber 6, Construction Calc, Handyman Calculator and the like, and the Construction Master Pro
   user guide. Output: `research/reviews.md` (quotes clustered by theme with counts) and `research/features.md`.
2. **Spec second**, in the Curata `mvp/` style: ontology, SPEC with "Do not build", screens, copy, formulas with
   published worked examples as oracles, edge cases, tests, `features.json` with `passes` flags. Calculator
   pain points P-01..P-13 each map to a spec rule or a feature (`spec/calculator/pain-points.md`).
3. **Skeleton and gate** before any screen: XcodeGen project, three packages with enforced boundaries,
   swiftlint/swiftformat, `verify.sh` with a test-count ratchet, protected-path hook (the gate enforces it at
   merge time; the in-editor hook file could not be written, see §8).
4. **Build in feature order**, Calo first (parity with `src/` function by function), then the calculator
   engine (pure, exhaustively unit-tested) before any calculator UI, then functions, settings, looks.
5. **Adversarial review** by read-only subagents before each significant commit (two rounds of 15 findings
   each on the first cut; a third set during the parity push). Every must-fix applied; the rest logged.
6. **UI tests and audits** last in each pass; audit rules were never relaxed to get green (the only
   subtractions are the three logged in §7).
7. **Parity push** on Walt's instruction at ~08:10: three agents in parallel, each on new files only, each
   function reproduced to the 1/16 against the user guide's examples.

## 4. What was built

### Calo (native)
- Main screen identical in function to the web app: header with the three-width date, dash (logged /
  remaining with rolling digits), optional item and details fields, intent display, 4×5 keypad with
  `+ − C ⌫`, bonus keys 80/60/40/20, `00`, Enter. Keys are the web `keyButton.css` design (charcoal, bonus
  grey, dark-orange intents with the active one lit inside a white outline, orange actions, gradient ring,
  90 ms press). Glass keys remain under Experiments → Calo keys.
- Settings sheet: Today's Log, About, show-name / show-details toggles, daily target, Experiments, clear
  daily log (two-tap confirm). Today's Log with edit sheet and swipe to delete. About.
- Day rollover at local midnight, error line, accessibility labels and announcements.
- Storage: GRDB (`GRDBLogStore`) with explicit migrations; `MemoryLogStore` for tests and the UI-test seed.
- Deviations from the web app, all logged: no dead "Reports" button; zero-only entries not logged; swipe to
  delete and tap to edit; Settings is a sheet; light mode exists; Enter clears the keypad before the write
  and restores it if the write fails.

### Construction calculator
- **Engine (`CalcKit`)**: exact `Fraction` (Int storage, Int128 intermediates, checked arithmetic, failable
  approximation), `Measure` (scalar, length, area, volume, angle; base inches), `DisplayUnit` cycles per
  kind (ft-in, decimal ft, in, yd, mm, cm, m; sq and cu families; degrees, pitch, % grade, D:M:S),
  `Precision` (1/2 … 1/64, exact; display-only rounding; ≈ when rounding changed the value), `EntryEngine`
  (typed tokens, parentheses, + − × ÷, %, ±, π, undo, memory, shunting-yard evaluation with percent
  folding, dimensional algebra, error states, magnitude cap), `Tape` (200 lines), `HistoryStore` (atomic
  JSON), `CalcPreferences`, `NaturalEntry` (type `5' 3 1/2"`, `7/12`, `30°`, `58.8%`, `1500 mm`, `2 cu yd`).
- **Entry convention** (Construction Master's rule, adopted after review): the inch mark separates whole
  inches from a fraction, `5 ′ 3 ″ 1 ⁄ 2` shows `5′ 3-1⁄2″`. A bare number added to a length is inches
  (mm in metric) and the expression line says so.
- **16 functions** in one registry, each with fields, live results, "Use" to send a result to the keypad,
  hold-to-see help with a worked example: Stairs, Roof (pitch, common, hip/valley, jacks, area),
  Irregular hip/valley (both jack sets, mate mode), Rake wall, Arched wall (inside and outside), Concrete
  (slab, footing, column, waste, bags), Board feet (count and cost), Square-up / diagonal, Circle & arc,
  Compound miter, Polygon, Studs, Drywall, Blocks / bricks / pavers, Balusters, Weight.
- **Screens**: expression line, result with unit chip and precision chip, 5×5 keypad, toolbar pill (undo,
  tape, functions, memory, settings), hold any key for help, Formats sheet (every unit at once), Tape sheet
  (reuse, delete, clear), Functions sheet and detail, Settings (unit system, precision, look, stair
  defaults, concrete waste and bag, o.c. spacing, Experiments).
- **Five looks**: Classic (default: real-calculator keys that sink into a darker base, role colours), Glass,
  Tape, Daylight, Blueprint.
- **Persistence**: engine state, memory, tape and settings survive lock, switch and relaunch.

### Shared
- Experiments → Open as (Calo / Calculator) switches product on sheet dismiss; `-calo.openAs` launch
  argument for tests. The two products share `DesignSystem` and nothing else, so a later App ID split is a
  `project.yml` change.
- One strings catalog (261 keys), no literal strings in views (a lint test enforces it), privacy manifest.

## 5. Research → pain points → what resolved them
Counts are review quotes in `research/reviews.md`.
| Pain point | Quotes | Resolution in the app |
|---|---|---|
| P-01 price, subscriptions, locked keys, ads | 49 | Free. No ads, purchases, accounts, network, analytics. Nothing to restore (P-12). |
| P-02 fraction entry fights the user | 14 | Type it as it reads off the tape; backspace through any token; expression shown as typed; natural entry in function fields. |
| P-03 cryptic key sequences vs fidelity | 10 | Functions are sheets with labelled fields and a results list; hold any key or field for help with a worked example. |
| P-04 1/16 rounding read as a bug; no mm / decimal readout | 10 | Precision chip always visible, ≈ when rounding changed the value, exact fraction in the Formats sheet, every unit one tap away. |
| P-05 memory and entry vanish on lock / relaunch | 5, 8 | Engine state, memory, tape and settings restored on launch. |
| P-06 no history, tape or undo | 8 | Tape of every `=` with expression and result, tap to reuse, undo key. |
| P-07 small keys, small text, no dark mode | 9 | Keys ≥ 56 pt, Dynamic Type everywhere but the capped key labels, light and dark, five looks incl. Daylight. |
| P-08 unit modes confusing, metric an afterthought | 4, 7 | One unit chip, metric at parity, no modes. |
| P-09 missing parentheses, π, rafter and stair cases | 7 | Parentheses and π on the keypad; irregular hip, rake wall, arched wall, riser-limited stairs. |
| P-10 wrong answers after updates | 6 | Every formula unit-tested against a published worked example; exact arithmetic end to end. |
| P-11 needs a connection | 12 | No network code exists. |
| P-13 praise to copy | — | Hold-a-key help, full expression on screen, multi-format results all shipped; the triple keypad was a deliberate no (one keypad, natural entry). |

Still out, by choice (SPEC "Do not build"): paint, tile, decking and fence estimators; per-unit cost beyond
board feet; "Constant" fraction mode; Jobber-style sixteenths entry; projects, export, sharing; trig keys.

## 7. Decisions Walt may want to overrule (details in PROGRESS.md)
- GRDB over SwiftData for Calo; JSON files for the calculator.
- Calo follows the system appearance (the web app was dark only).
- The entry convention above (inch mark as separator; bare number = base unit, shown).
- Volume results default to cubic yards in imperial; code limits (IRC R311.7) are shown as warnings, never enforced.
- Audit subtractions: contrast rule off on glass screens (Walt's Curata call); Dynamic Type rule off on the two
  keypad screens only (the spec caps key labels); Calo's settings sheet audited at the large detent.
- Header date is one variant at natural size, not the three-way fit (the clipped-text rule flagged the fitted
  variant and I would not subtract that rule).
- Settings Done lives in a footer beside Clear, not in the toolbar (the bar button ignores Dynamic Type).
- Haptics as `SensoryFeedback` constants so DesignSystem stays SwiftUI-only.
